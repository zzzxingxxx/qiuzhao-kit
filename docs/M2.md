# M2 任意网申页 AI 预填

已完成。主路径是 **当前打开的任意网申页**，用本机 AI 把表单字段对到档案 / 简历，人确认后再写入。  
**不是**「先认出北森再填」。北森、Moka、飞书招聘、公司自建页都走同一套。

预填不等于代投。提交按钮、验证码、登录框一律停下来等人。

## 为什么不用旧写法

旧阶段名是「北森预填」：按 ATS 品牌写 DOM 对照表。现在校招网申分散在各公司站点，北森占比已经不高。按站点维护对照表会过时。

较新的做法：页面只负责抽出「有哪些题」，对字段交给本机已有的 AI（SpaceXAI，密钥仍只在本机服务）。认不认得出 ATS 不影响能不能用。

## 目标

人在任意网申页点「预填此页」之后：

1. 扩展扫描本页可见表单（标签、类型、选项、是否必填），不上传整页 HTML、不读密码框。
2. 本机服务拿到表单骨架 + 当前档案 / 简历，先用标签规则对照，有密钥时再让模型补复杂题。
3. 弹出核对：将填、不确定、档案里没有。人可以改某一格或跳过。
4. 点确认后，扩展只写入对应输入框。不点提交，不点下一步里的「提交报名」。
5. 对不上的项列入 `missingFields`，供 M3 看板使用。

无 API Key 时提示去网页「设置」，仍可用姓名 / 手机 / 邮箱等规则对照。不改 SpaceXAI 的地址 / 密钥存法。

## 数据怎么对

来源仍是本机已有结构，不另做一套「北森字段」：

| 页面常见题 | 用哪份数据 |
| --- | --- |
| 姓名、性别、证件、手机、邮箱、政治面貌、城市 | 档案 Profile |
| 学校、专业、学历、在校时间、GPA | 档案 education |
| 到岗、期望城市、薪资、英语四级等问卷 | 档案 qa |
| 实习、项目、技能、评价 | 当前简历 Resume（身份和教育仍以档案为准） |

模型只许用这些事实。禁止编造没写过的公司、数字、证书。教育 / 身份不从简历里猜。

## 本机接口

复用 `/ai/chat` 的密钥与上游，专用动作 `POST /ai/map-form`：

- 入参：表单骨架（题干、控件类型、选项）、可选 `pageUrl` / `pageTitle`。档案和简历由服务端读取，扩展不上传整页 HTML。
- 出参：JSON 对照表 `{ fields, missingFields, usedAi, needsKey }`。
- 扩展只把这份对照表给用户看，确认后再写 DOM。

`packages/fill`：抽表单骨架、标签规则对照、把对照表写回输入框。ATS 名字只做备注，不是门槛。

## 扩展

- 当前页 content script：抽字段、高亮、按确认结果写入。
- Popup：「预填此页」+ 将填 / 不确定 / 缺项。连通性检查保留。
- 只请求 `http://127.0.0.1:8787`。不导出 Cookie，不在云端存表单。

演示页（非北森）：[http://127.0.0.1:5173/apply-demo.html](http://127.0.0.1:5173/apply-demo.html)

## 验收

- 在**不是北森**的普通表单页（本地 fixture 或任意带 label 的申请表）能生成对照表。
- 人确认后，姓名 / 手机 / 邮箱等能写入可见输入框。
- 提交按钮在整个过程中不被点击。
- 档案空项显示为缺项，而不是模型编造。
- 未配置密钥时走设置页，不把 Key 打进扩展包。

## 明确不做

自动提交、自动过验证码、云端代投、导出 Cookie、Boss 海投当主功能、按单一 ATS 写死选择器当主路径。

热门站点的补丁（自定义下拉、iframe）可以后补，属于准确率加成，不挡 M2 完成。

## 和 M3 的边界

M2 负责「这一页填了什么、缺什么」。  
M3 把一次预填记成投递卡片（公司、链接、简历版本、状态、缺项）。看板闭环不在本阶段。

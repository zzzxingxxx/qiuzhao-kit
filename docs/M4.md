# M4 校招信息汇总去重

**未实现。本文只定方案，不写代码。**

把 [纸条推推招聘列表](https://offertt.cn/recruitment) 和 [求职方舟校招汇总表](https://www.qiuzhifangzhou.com/campus) 的公开校招条目，拉到本机秋招助手里：**归一、去重、可筛选**，需要时再记入 M3 投递看板。

这不是再做一个对外的汇总站。数据只进本机 SQLite，页面仍是 `http://127.0.0.1:5173`。预填不等于代投，本阶段也不自动打开网申、不代点提交。

## 要解决什么

现在两份列表各看各的，同一家公司、同一条网申会重复出现。希望在本站有一份「机会列表」：

1. 人点「同步」后，本机去拉两站当前公开接口。
2. 收成统一结构（公司、岗位、城市、批次、截止、公告、网申链接）。
3. 按链接和公司名去重，重复来源记在同一条上。
4. 网页可搜、可筛；点「记入看板」才变成 M3 投递卡（状态默认待投）。

## 和现有模块的边界

| 模块 | 管什么 |
| --- | --- |
| M3 投递看板 `Application` | **我**投过 / 预填过的卡 |
| M4 机会列表 `JobListing` | **市场上**还在招的条目 |

两张表不要合成一张。机会列表可以生成看板草稿，看板不反过来当招聘库。

实习汇总（方舟 `/campus?table=intern`）本阶段不做主路径，方案里只预留来源标记。热门站点 DOM 补丁仍不属于本阶段。

## 源站怎么取（已核对，实现时再回归一次）

两边都是前端 SPA，**不要无头浏览器扒 HTML**。走它们页面自己用的 JSON。接口路径、鉴权和字段可能改，适配器必须可替换。

### 纸条推推 `offertt.cn`

- 列表：`GET https://offertt.cn/api/campus-recruitments/v2?page=&page_size=`
- 详情：`GET https://offertt.cn/api/campus-recruitments/{id}`
- 筛选项：`GET https://offertt.cn/api/campus-recruitments/filter-options/v2`
- 匿名能力只有 `recruitment.list.first_page`。实测：第 1 页（含 `page_size=100`）可匿名；**第 2 页返回 403**，`capability: recruitment.list.paginate`，需要登录/会员。全库约三千多条，匿名拿不全。
- 条目字段（列表已有）：`id`、`company_name`、`job_names[]`、`locations[]`、`recruitment_batch`、`recruitment_target_years[]`、`education_requirement`、`deadline`、`application_status`、`announcement_url`、`apply_url`、`company_type`、`industry_primary` / `industry_secondary`、`update_tag`、`referral_note`

**本阶段策略：** 只吃匿名第一页，用来补全字段（岗位数组、届次、学历）。**不登录对方账号，不保存对方 Cookie，不绕过会员翻页。** 完整覆盖以方舟按日表为主。

### 求职方舟 `qiuzhifangzhou.com`

- 校招表：`POST https://api.qiuzhifangzhou.com/api/campus/getCampusList`
- 请求体：`{ "dateList": [{ "date": "YYYY-MM-DD", "md5": "" }] }`。日期是最近若干天（站点用本地缓存天数）；`md5` 与上次相同则那天可视为未变。
- 响应：`{ campusList: [{ date, md5, datas: JobRow[] }] }`
- 行字段：`id`、`company`、`positions`（顿号拼的字符串）、`locations`、`deadline`、`batch`、`industry`、`typeTag[]`、`noticeUrl`、`applyUrl`、`sourceUrl`、`urlType`、`referralCode`、`popular`、`createTime`
- 前端会丢掉 `deadline` 早于当天的行。本机同步时同样过滤，另保留「已过期」开关给回顾。
- 同一接口按天增量，匿名可拉近日全量，适合当主源。

## 本机数据契约（拟定，实现时放 `packages/schema`）

```ts
jobListingSchema = {
  id,                    // 本机 id
  company,               // 去后缀后的展示名，另存 companyRaw
  jobTitles: string[],   // 拆开的岗位
  locations: string[],   // 城市，可带省份
  batch,                 // 秋招 / 27秋招 / 实习…
  years: string[],       // 2026 / 2027
  education,             // 本科及以上
  deadline,              // 日期或「招满即止」
  status,                // 招聘中 / 未知
  applyUrl,
  noticeUrl,
  industry,
  companyType,           // 民营 / 国企…
  sources: [{ site: "offertt" | "fangzhou", sourceId: string, syncedAt }],
  fingerprint,           // 去重键
  firstSeenAt,
  lastSeenAt,
  expired: boolean,
}
```

SQLite 新表 `job_listings`，不要塞进 `applications`。`fingerprint` 建唯一索引。

## 归一

适配器输出同一中间结构，再写入。

| 统一字段 | 纸条推推 | 求职方舟 |
| --- | --- | --- |
| 公司 | `company_name` | `company`（去掉「有限公司」等后缀仅用于匹配） |
| 岗位 | `job_names[]` | `positions` 按 `、,;/` 切开 |
| 城市 | `locations[].city` 或 `province` | `locations` 按空白/顿号切开 |
| 批次 | `recruitment_batch` | `batch` |
| 届次 | `recruitment_target_years` | 从 batch 里解析「27」→ 2027，解析不到则空 |
| 学历 | `education_requirement` | 无则空 |
| 截止 | `deadline` | `deadline` |
| 网申 | `apply_url` | `applyUrl` |
| 公告 | `announcement_url` | `noticeUrl` / `sourceUrl` |

链接一律走现有 `normalizeApplyUrl`（去 hash、去 utm）。微信公告用 `mp.weixin.qq.com/s/` 后的 ID 当稳定键。

## 去重

按优先级命中即视为同一条，**合并而不是丢弃**：

1. 规范化后的 `applyUrl`（非空、且不是纯官网首页）。
2. 规范化后的微信/公告 URL。
3. `公司归一名 + 批次归一 + 届次`（三件都有才用）。

公司归一：去空白、全角转半角、去掉 `股份有限公司|有限责任公司|有限公司|集团|总部`。不做过度模糊（「米奇化工」vs「广州米奇化工」第一期宁可两条，也不要误伤成一家）。

合并规则：岗位、城市、来源做并集；网申链接优先「像申请表的 URL」，其次公众号；截止日期取更具体的日期，而不是「招满即止」；`lastSeenAt` 取新，`firstSeenAt` 保留旧。已在 M3 看板里出现过的 `applyUrl`，列表上打「已在看板」标记，不自动改看板状态。

## 本机接口（拟定）

- `POST /jobs/sync`：人点同步。串行拉方舟近日 + 纸条推推第一页。返回 `{ fetched, upserted, merged, skippedExpired, warnings }`。进行中禁止重入。
- `GET /jobs`：分页 + `q` / `city` / `batch` / `industry` / `source` / `expired`。
- `POST /jobs/:id/to-board`：用该条的公司、岗位（可多选一个）、`applyUrl` 调现有建卡逻辑，状态 `draft`。已有相同链接则返回那张卡，不新建。

同步失败时保留上次库，用 `warnings` 说明哪一个源失败。不要因为一源 403 把另一源也丢掉。

## 网页

新页 `/jobs`（名称「校招信息」或「机会」），顶栏与工作台、看板并列。

- 工具条：同步、上次同步时间、条数、来源失败提示。
- 筛选：搜索公司/岗位、城市、批次、行业、来源。
- 列表：公司、岗位（折叠显示）、城市、批次、截止、来源小标、网申/公告链接。
- 操作：打开网申（新标签，人手点）、记入看板。
- 不抄两站的 Excel/会员样式。

扩展弹窗本阶段不必加机会列表。从机会点进网申后，仍用现有「预填此页」。

## 同步策略

- **默认只手动同步**，避免当爬虫常驻。
- 方舟用日期 + md5，未变的天不重写。
- 两次同步最短间隔（例如 10 分钟），超时单独计（建议 30 秒/源）。
- User-Agent 标明本机工具名；并发 1；不打验证码、不打登录框。
- 源接口一变，只改 `apps/server` 里对应 adapter，不要把选择器写进 Vue。

## 验收（实现时）

- 点同步后，本机列表能看到方舟近日条目 + 纸条推推第一页条目。
- 同一网申链接在两边都有时，只显示一条，来源显示两个站点。
- 过期条目默认隐藏。
- 「记入看板」后 `/board` 出现待投卡，再预填仍更新同一张卡。
- 纸条推推第 2 页 403 时给出中文说明（匿名只有首页），不同步失败、不引导去导出 Cookie。
- 不登录、不提交、不把列表发布到公网。

## 明确不做

- 实现代码（本文件不是开工令）。
- 公开镜像站、定时对外提供汇总 API。
- 登录纸条推推 / 求职方舟、保存对方 Cookie、绕过会员翻页。
- 自动打开网申并填写、自动提交、过验证码。
- 无头 Chrome 扒页面。
- Boss 直聘海投。
- 抄两站的界面或把他们的文案整页搬过来。

## 风险

- 两站接口随时改路径或加鉴权，适配器必须隔离。
- 纸条推推匿名覆盖面只有首页；完整度取决于方舟近日表，不是「全网校招」。
- 对方 ToS 可能不欢迎批量拉取：仅本机自用、人点同步、限速。若源站明确禁止，就停掉对应 adapter。
- 岗位字符串脏（「管培生、研发」和数组「管培生」）去重以链接为准，岗位只做展示合并。
